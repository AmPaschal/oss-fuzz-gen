
	
<description>
This function, `clib_package_install`, is responsible for installing a clib package. It takes a `clib_package_t` object, a directory path, and a verbosity flag as input.

The function performs the following main operations:
1.  **Initialization and Pre-checks**: It initializes local variables and performs checks on the input arguments (`pkg` and `dir`). It also initializes a global hash map `visited_packages` on its first run to keep track of installed packages and avoid circular dependencies. It also sets up a prefix for installation, reading from a global `opts` struct or environment variables.
2.  **Directory and Manifest Handling**: It creates a directory for the package within the specified `dir`. It also writes the package's JSON manifest (`clib.json` or `package.json`) to this directory.
3.  **Fetching Source Files**: It fetches the source files listed in the package's manifest. If pthreads are enabled, it can do this concurrently. It has logic to handle caching of packages to avoid re-downloading.
4.  **Installation**: It runs the package's `configure` script if it exists. It then proceeds to install the package's executables and dependencies by calling `clib_package_install_executable` and `clib_package_install_dependencies`.
5.  **Caching**: After a successful installation, it caches the package for future use.
6.  **Cleanup**: It cleans up allocated resources. If an error occurred, it removes the partially installed package directory.

The callers of this function, such as `install_packages`, first create a `clib_package_t` object by parsing a package slug (e.g., "author/repo@version") using `clib_package_new_from_slug`. This function fetches the package's manifest from a remote source and populates the `clib_package_t` struct with the necessary information like name, version, source files, and dependencies. This populated struct is then passed to `clib_package_install`.

The function's behavior is heavily influenced by the global `opts` struct, which contains flags like `force`, `global`, `skip_cache`, and `concurrency`. These flags control aspects like re-installation, global vs. local installation, cache usage, and the number of download threads.
</description>
<requirements>
<requirement>
The first argument, `pkg`, must be a non-NULL pointer to a valid `clib_package_t` struct. This is because the function dereferences this pointer to access package information without a prior NULL check in all cases.
</requirement>
<requirement>
The `pkg` argument should be initialized by calling `clib_package_new_from_slug()` or `clib_package_new()`. This ensures that the struct's fields, such as `name`, `author`, `version`, `src`, and `json`, are correctly populated from a package manifest.
</requirement>
<requirement>
The `pkg->name`, `pkg->author`, and `pkg->version` fields must be valid, null-terminated strings. These fields are used for creating directory paths, constructing URLs, and as keys for caching, so they must be valid.
</requirement>
<requirement>
The second argument, `dir`, must be a non-NULL, null-terminated string representing a path to a writable directory. This is because the function will attempt to create a subdirectory within this path to install the package.
</requirement>
<requirement>
The global `opts` struct must be initialized before calling this function. The fields `opts.prefix`, `opts.force`, `opts.global`, `opts.skip_cache`, and `opts.concurrency` control the installation behavior and should be set to desired values.
</requirement>
</requirements>
