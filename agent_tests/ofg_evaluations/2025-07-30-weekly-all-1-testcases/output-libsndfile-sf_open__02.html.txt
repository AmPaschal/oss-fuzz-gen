
	
<description>
The function `sf_open` opens a sound file specified by `path` with the given `mode`. It uses the `sfinfo` struct to determine the properties of the file to be created (if opened for writing) or to store the properties of the file being read. The `path` can be a file path or `"-"` for stdin/stdout. The function returns a pointer to a `SNDFILE` structure on success or `NULL` on error.
</description>
<requirements>

<requirement>
The `path` argument should be a null-terminated string representing a valid file path, or the special string `"-"` for standard I/O. This is because the function attempts to open the path and a non-existent path will cause an error.
</requirement>
<requirement>
The `mode` argument must be one of `SFM_READ` (0x10), `SFM_WRITE` (0x20), or `SFM_RDWR` (0x30). Using other values will result in undefined behavior as the function specifically checks for these modes.
</requirement>
<requirement>
The `sfinfo` argument must be a non-NULL pointer to a valid `SF_INFO` structure. The function dereferences this pointer, so a NULL pointer would cause a crash.
</requirement>
<requirement>
When the `mode` is `SFM_WRITE` or `SFM_RDWR`, the `format`, `samplerate`, and `channels` fields of the `SF_INFO` struct must be initialized with valid values. The function uses these values to create the header of the new sound file.
</requirement>
<requirement>
The `sf_format_check` function should be called to validate the `SF_INFO` structure before calling `sf_open` in write mode. This ensures the combination of format, sample rate, and channels is valid and supported by the library.
</requirement>

</requirements>
