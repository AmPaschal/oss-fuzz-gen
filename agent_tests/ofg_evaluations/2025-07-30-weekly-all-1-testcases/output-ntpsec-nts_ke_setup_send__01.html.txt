
	
<description>
The function `nts_ke_setup_send` constructs a response for the NTS-KE (Network Time Security Key Exchange) protocol. It assembles several records, including protocol negotiation, AEAD algorithm negotiation, and a number of cookies, into a buffer provided by the caller. This buffer is then intended to be sent to the client over a TLS connection. The function relies on valid cryptographic keys and algorithm identifiers passed as arguments to generate the cookies.
</description>
<requirements>

<requirement>
The `buf` argument must be a pointer to a valid `BufCtl_t` struct. `buf->next` should point to a buffer of at least 2048 bytes, and `buf->left` should be initialized to the size of that buffer, as the function writes multiple records, including up to 8 cookies of 100 bytes each.
</requirement>
<requirement>
The `aead` parameter should be initialized to a valid AEAD algorithm identifier, such as `AEAD_AES_SIV_CMAC_256` (15). This is because it is used to select the cryptographic algorithm for generating cookies.
</requirement>
<requirement>
The `keylen` parameter must be the correct key length in bytes corresponding to the `aead` algorithm. You can use the `nts_get_key_length` function to determine the correct value.
</requirement>
<requirement>
The `c2s` and `s2c` pointers must point to buffers that are at least `keylen` bytes long. These buffers should contain the client-to-server and server-to-client keys generated by a function like `nts_make_keys`.
</requirement>
<requirement>
The `extra_port` global variable should be initialized to a valid port number if used. This variable is used to add an optional `nts_port_negotiation` record to the response.
</requirement>

</requirements>
