
	
<description>
The `tidyParseSource` function is a wrapper around `tidyDocParseSource`. It parses the input provided by the `TidyInputSource` and associates it with the `TidyDoc` document. The `TidyInputSource` can be created from a file, a buffer, or a stream. For fuzzing, the most convenient way is to create it from a buffer. The steps are: create a `TidyDoc` using `tidyCreate`, initialize a `TidyBuffer` using `tidyBufInit`, append the raw fuzzing data to the buffer using `tidyBufAppend`, create a `TidyInputSource` from the buffer using `sourceFromBuffer`, and then call the target function. Finally, the created resources should be freed.
</description>
<requirements>

<requirement>
The `TidyDoc` argument should be created by calling `tidyCreate()`. This is because the function expects an initialized `TidyDocImpl` struct, which is allocated and initialized by `tidyCreate`.
</requirement>
<requirement>
The `TidyInputSource` argument should be initialized using `sourceFromBuffer()`. The `TidyInputSource` struct contains function pointers that need to be set correctly, and `sourceFromBuffer` handles this for buffer-based input, which is ideal for fuzzing.
</requirement>
<requirement>
A `TidyBuffer` must be initialized using `tidyBufInit()` and populated with data using `tidyBufAppend()` before being passed to `sourceFromBuffer()`. This is because `sourceFromBuffer` reads from the `TidyBuffer` to create the `TidyInputSource`.
</requirement>
<requirement>
After calling `tidyParseSource`, the `TidyDoc` and `TidyBuffer` should be freed using `tidyRelease()` and `tidyBufFree()` respectively. This is to prevent memory leaks.
</requirement>

</requirements>

#include <stddef.h>
#include <stdint.h>

#include "/src/tidy-html5/include/tidy.h"
#include "/src/tidy-html5/include/tidybuffio.h"

// Custom data structure to hold the state of the fuzzer's input buffer.
// This will be passed to the TidyInputSource callbacks.
typedef struct {
  const uint8_t *data;
  size_t size;
  size_t offset;
} FuzzInput;

// Callback function for Tidy to get the next byte of input.
// It reads from our FuzzInput buffer.
static int fuzz_get_byte(void *sourceData) {
  FuzzInput *input = (FuzzInput *)sourceData;
  if (input->offset < input->size) {
    return input->data[input->offset++];
  }
  return -1; // Indicates EOF
}

// Callback function for Tidy to "unget" a byte.
// We simply decrement our position in the FuzzInput buffer.
static void fuzz_unget_byte(void *sourceData, byte bt) {
  (void)bt; // The byte value is not used in this implementation.
  FuzzInput *input = (FuzzInput *)sourceData;
  if (input->offset > 0) {
    input->offset--;
  }
}

// Callback function for Tidy to check if the end of the input has been reached.
static Bool fuzz_eof(void *sourceData) {
  FuzzInput *input = (FuzzInput *)sourceData;
  return (input->offset >= input->size) ? yes : no;
}

int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
  TidyDoc tdoc = tidyCreate();
  TidyBuffer errbuf;
  tidyBufInit(&errbuf);

  // Set an error buffer to capture diagnostics and prevent them from
  // being printed to the console, which would slow down fuzzing.
  tidySetErrorBuffer(tdoc, &errbuf);

  // Initialize our custom input state with the fuzzer-provided data.
  FuzzInput fuzz_input;
  fuzz_input.data = data;
  fuzz_input.size = size;
  fuzz_input.offset = 0;

  // Set up the TidyInputSource with our custom callbacks.
  TidyInputSource source;
  source.sourceData = &fuzz_input;
  source.getByte = fuzz_get_byte;
  source.ungetByte = fuzz_unget_byte;
  source.eof = fuzz_eof;

  // Call the function under test.
  tidyParseSource(tdoc, &source);

  // It's good practice to also exercise the cleaning and saving phases
  // to find deeper bugs.
  TidyBuffer output;
  tidyBufInit(&output);
  tidyCleanAndRepair(tdoc);
  tidySaveBuffer(tdoc, &output);

  // Clean up all allocated resources.
  tidyBufFree(&output);
  tidyBufFree(&errbuf);
  tidyRelease(tdoc);

  return 0;
}
