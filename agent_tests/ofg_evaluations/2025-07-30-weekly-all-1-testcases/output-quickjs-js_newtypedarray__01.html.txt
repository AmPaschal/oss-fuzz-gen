
	
<description>
The `JS_NewTypedArray` function is a factory for creating various JavaScript TypedArray objects (e.g., Uint8Array, Int32Array, Float64Array). It serves as a wrapper for the internal `js_typed_array_constructor` function, performing an initial validation of the `type` parameter. The constructor logic it calls supports two main modes of operation: creating a new TypedArray of a specified length, which involves allocating a new underlying ArrayBuffer, or creating a TypedArray that acts as a view over an existing ArrayBuffer, with a specified offset and length.
</description>
<requirements>
<requirement>
A valid `JSContext *` must be provided, which is created by calling `JS_NewRuntime()` followed by `JS_NewContext()`. This context is essential for all operations within the QuickJS engine.
</requirement>
<requirement>
The `type` argument must be a value from the `JSTypedArrayEnum` enum, specifically between `JS_TYPED_ARRAY_UINT8C` (0) and `JS_TYPED_ARRAY_FLOAT64` (12). The function will throw a `RangeError` for any values outside this range.
</requirement>
<requirement>
To create a typed array by specifying a length, `argc` must be 1 and `argv[0]` should be a `JSValue` representing that length. This value can be created using `JS_NewUint32(ctx, length)`.
</requirement>
<requirement>
To create a typed array as a view on an existing buffer, `argv[0]` must be a `JSValue` holding an `ArrayBuffer` object. Such a buffer can be created with `JS_NewArrayBufferCopy()`.
</requirement>
<requirement>
When creating a view on an existing buffer, the offset passed in `argv[1]` must be a multiple of the typed array's element size. This is to prevent the internal constructor from raising a `RangeError`.
</requirement>
<requirement>
When creating a view, the combination of offset and length must not exceed the bounds of the source `ArrayBuffer`. The condition `offset + (length * bytes_per_element) <= buffer_byte_length` must hold to avoid a `RangeError`.
</requirement>
</requirements>
