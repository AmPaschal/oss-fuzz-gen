The `utf8proc_decompose` function is responsible for decomposing a UTF-8 string into a sequence of Unicode codepoints. It serves as a simplified interface to the `utf8proc_decompose_custom` function, pre-configuring it to perform decomposition without any custom character mappings.

A common usage pattern for this function, as observed in the project's own `utf8proc_map_custom` function, involves a two-step process. First, `utf8proc_decompose` is called with a `NULL` buffer and a buffer size of `0`. This initial call doesn't perform any decomposition but instead calculates and returns the required buffer size for the given input string and options. If this pre-flight check is successful, the caller then allocates a buffer of the determined size. The second call to `utf8proc_decompose` then uses this allocated buffer to perform the actual decomposition, writing the resulting Unicode codepoints into it. This two-step approach ensures that the buffer is always appropriately sized, preventing potential buffer overflows.

The behavior of the decomposition is controlled by the `options` parameter, which is a bitmask of flags. These flags allow for various transformations of the Unicode data, such as normalization (NFD, NFC, NFKD, NFKC), case-folding, and stripping of control characters. However, not all combinations of these flags are valid. For instance, the `UTF8PROC_COMPOSE` and `UTF8PROC_DECOMPOSE` options are mutually exclusive. Similarly, the `UTF8PROC_STRIPMARK` option can only be used in conjunction with either `UTF8PROC_COMPOSE` or `UTF8PROC_DECOMPOSE`. Invalid option combinations will cause the function to return an error.
