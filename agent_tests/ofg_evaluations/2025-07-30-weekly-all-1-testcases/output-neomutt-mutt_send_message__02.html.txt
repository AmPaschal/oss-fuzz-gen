
	
<description>
This function is the core of neomutt's email sending capabilities. It's a large, multifaceted function responsible for handling all aspects of composing and sending an email. Its behavior is primarily controlled by the `flags` parameter, which dictates the sending context, such as creating a new message, replying, forwarding, resending a message, or recalling a postponed one.

The function begins by setting up the email template (`e_templ`). If one isn't provided, it creates a new one. Depending on the `flags`, it might populate the template from a postponed message, a message to be resent, or by setting up headers for a reply or forward. It then enters a phase where it can interact with the user to edit the message envelope (recipients, subject, etc.) and the message body.

A significant portion of the function is dedicated to handling cryptographic operations like PGP and S/MIME signing and encryption. It automatically determines whether to apply security measures based on user configuration, the context of the message (e.g., replying to an encrypted email), and can interact with crypto backends.

After the user has finished editing and confirmed the message, the function performs final preparations, such as encoding the content and preparing the envelope. It then handles saving a copy of the message to an FCC (Folder Carbon Copy) folder before or after invoking the system's Mail Transfer Agent (MTA) to perform the actual sending. Finally, it performs cleanup, freeing allocated resources and setting flags on the original message if it was a reply.
</description>
<requirements>
<requirement>
The `sub` argument must be a valid pointer to an initialized `struct ConfigSubset`. This is critical as the function repeatedly calls configuration-retrieving functions (`cs_subset_bool`, `cs_subset_string`, etc.) using this pointer without any null checks.
</requirement>
<requirement>
The `e_templ` argument can be NULL, in which case a new email structure is allocated internally. If it is not NULL, it must point to a valid `struct Email` object, which is typically created using the `email_new()` function.
</requirement>
<requirement>
If a non-NULL `e_templ` is provided, its `env` member (`e_templ->env`) should also point to a valid, initialized `struct Envelope`, typically created via `mutt_env_new()`. The function relies on this to store and manipulate email headers.
</requirement>
<requirement>
If the `SEND_DRAFT_FILE` flag is set, the `e_templ` argument must not be NULL, and its `body->filename` member must point to a valid, readable file path. The function will attempt to open this file to populate the message body.
</requirement>
<requirement>
If the `SEND_POSTPONED` flag is set, the `m` argument must be a valid pointer to a `struct Mailbox`. The function will use this mailbox to retrieve the postponed message that is to be sent.
</requirement>
<requirement>
The `ea` argument, which is a pointer to a `struct EmailArray`, can be NULL. If it is not NULL, it must be a valid array of `struct Email` pointers, as the function will iterate over it to get context from the original emails when replying or forwarding.
</requirement>
<requirement>
The `tempfile` argument can be NULL. If it is not NULL, it must be a string representing a writable file path, as the function will attempt to open it for appending with `mutt_file_fopen`.
</requirement>
<requirement>
The `flags` argument must be a valid combination of `SendFlags` values. The presence of certain flags, such as `SEND_POSTPONED` or `SEND_DRAFT_FILE`, imposes specific requirements on the other function arguments.
</requirement>
</requirements>
