
	
<description>
The function `H5D__write` is a core internal function in the HDF5 library responsible for writing data to one or more datasets. It is not intended to be called directly by the application developer, but rather by other internal library functions that have already set up the necessary data structures.

The function takes two arguments: `count`, which specifies the number of datasets to write to, and `dset_info`, which is an array of `H5D_dset_io_info_t` structures. Each structure in this array contains all the necessary information for a write operation on a single dataset, including pointers to the dataset object, memory and file dataspaces, the memory buffer containing the data, and the data type.

The function's primary role is to iterate through the provided `dset_info` array and perform the write operation for each dataset. This involves:
- Performing numerous validation checks on the input structures.
- Preparing for I/O by setting up internal data structures (`io_info`).
- Handling different dataset storage layouts (e.g., contiguous, chunked).
- Managing data type conversions between memory and file.
- Invoking the appropriate low-level I/O routines to perform the actual write to the file.
- Handling complex scenarios like parallel I/O and projections of dataspaces.

Callers like `H5VL__native_dataset_write` first prepare the `H5D_dset_io_info_t` array by calling helper functions (e.g., `H5VL__native_dataset_io_setup`) and then invoke `H5D__write` to execute the write. It is crucial that the `dset_info` structures are fully and correctly populated before calling this function, as it relies on this information to perform the I/O correctly and safely.
</description>
<requirements>
<requirement>
The `dset_info->dset` field must be a valid and open dataset object created by a function like `H5Dcreate`. This is a fundamental requirement as the function dereferences this pointer multiple times to access dataset properties.
</requirement>
<requirement>
The file associated with the dataset (`dset_info->dset->oloc.file`) must be opened with read-write access (`H5F_ACC_RDWR`). The function explicitly checks for this permission and will fail if the file is read-only.
</requirement>
<requirement>
The number of elements selected in the memory dataspace (`dset_info->mem_space`) must be equal to the number of elements selected in the file dataspace (`dset_info->file_space`). A mismatch in the number of elements will result in an error, as the source and destination selections must correspond.
</requirement>
<requirement>
Both the memory and file dataspaces (`dset_info->mem_space` and `dset_info->file_space`) must have their extents set. The function checks this to ensure that the shapes and sizes of the dataspaces are well-defined before any I/O operation.
</requirement>
<requirement>
If the number of selected elements (`dset_info->nelmts`) is greater than zero, the buffer pointer `dset_info->buf.cvp` must not be NULL. A NULL buffer is only permissible when no data is actually being transferred, otherwise it is an error condition.
</requirement>
<requirement>
The `count` parameter must be a positive integer that correctly represents the number of `H5D_dset_io_info_t` structures in the `dset_info` array. An incorrect count can lead to out-of-bounds memory access on the array.
</requirement>
<requirement>
The `dset_info` array and its elements must be properly initialized by a higher-level setup function, such as `H5VL__native_dataset_io_setup`. This ensures that all necessary fields, including internal function pointers for layout-specific operations, are correctly populated.
</requirement>
<requirement>
A valid dataset transfer property list (DXPL) must be active, set via `H5CX_set_dxpl`, before calling `H5D__write`. This property list governs aspects of the data transfer, and not having one set can lead to undefined behavior.
</requirement>
</requirements>

#include "hdf5.h"

#include "H5Dpkg.h"

#include <string.h>

int

{
    if (size == 0) {
        return 0;
    }

    char filename[256];
    sprintf(filename, "/tmp/libfuzzer.%d", getpid());

    hid_t file_id = H5Fcreate(filename, H5F_ACC_TRUNC, H5P_DEFAULT, H5P_DEFAULT);
    if (file_id < 0) {
        remove(filename);
        return 0;
    }

    hsize_t dims[1] = {size};
    hid_t   space_id = H5Screate_simple(1, dims, NULL);
    if (space_id < 0) {
        H5Fclose(file_id);
        remove(filename);
        return 0;
    }

    hid_t dset_id = H5Dcreate2(file_id, "dset", H5T_NATIVE_UINT8, space_id, H5P_DEFAULT, H5P_DEFAULT, H5P_DEFAULT);
    if (dset_id < 0) {
        H5Sclose(space_id);
        H5Fclose(file_id);
        remove(filename);
        return 0;
    }

    H5D_t *dset_ptr = (H5D_t *)H5I_object_verify(dset_id, H5I_DATASET);
    H5S_t *space_ptr = (H5S_t *)H5I_object_verify(space_id, H5I_DATASPACE);

    if (dset_ptr && space_ptr) {
        H5D_dset_io_info_t dset_info;
        memset(&dset_info, 0, sizeof(H5D_dset_io_info_t));

        dset_info.dset = dset_ptr;
        dset_info.mem_space = space_ptr;
        dset_info.file_space = space_ptr;
        dset_info.buf.cvp = data;

        H5CX_set_dxpl(H5P_DEFAULT);

        H5D__write(1, &dset_info);
    }

    H5Dclose(dset_id);
    H5Sclose(space_id);
    H5Fclose(file_id);
    remove(filename);

    return 0;
}
