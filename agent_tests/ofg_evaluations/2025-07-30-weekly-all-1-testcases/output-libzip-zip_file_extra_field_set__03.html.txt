
	
<description>
The `zip_file_extra_field_set` function is used to add or modify an extra field for a file within a zip archive. It takes the archive pointer, the file index, the extra field ID and index, the data for the extra field, its length, and flags indicating where to store the extra field (local, central, or both). The function first performs several checks to ensure the archive is writable, the file index is valid, and the extra field ID is not for internal use. It then prepares the file entry for changes. It searches for an existing extra field matching the provided ID and index. If found, it replaces it; otherwise, it adds a new one. The total size of the extra fields is checked to prevent it from exceeding the 16-bit limit. The callers in `ziptool.c` and `zipmerge.c` show that the function is used for both creating new extra fields from user-provided data and for copying extra fields from another archive.
</description>
<requirements>
<requirement>
The `za` archive must be opened in a writeable mode. This is because the function checks `ZIP_IS_RDONLY(za)` and will fail if the archive is read-only.
</requirement>
<requirement>
The `idx` argument must be a valid index of a file in the archive. The function uses `_zip_get_dirent(za, idx, 0, NULL)` to get the directory entry, which will fail for an invalid index.
</requirement>
<requirement>
The `ef_id` must not be an internal extra field ID. The function checks `ZIP_EF_IS_INTERNAL(ef_id)` and returns an error for internal IDs.
</requirement>
<requirement>
The `ef_idx` argument should either be a valid index of an existing extra field or `ZIP_EXTRA_FIELD_NEW` (which is `ZIP_UINT16_MAX`). If it's not `ZIP_EXTRA_FIELD_NEW` and is out of bounds, the function will fail.
</requirement>
<requirement>
The `data` pointer should point to a buffer of at least `len` bytes. The function reads `len` bytes from `data` to create the new extra field.
</requirement>
<requirement>
The `len` argument, representing the length of the data, should be such that the total length of the extra fields does not exceed `ZIP_UINT16_MAX`. The function has a check to prevent this overflow.
</requirement>
<requirement>
The `flags` argument must include at least one of `ZIP_EF_LOCAL` or `ZIP_EF_CENTRAL`. The function checks `(flags & ZIP_EF_BOTH) == 0` and fails if neither is set.
</requirement>
<requirement>
The function `_zip_file_extra_field_prepare_for_change(za, idx)` must be called implicitly before this function. This is handled internally, but it implies the archive must be in a state where changes can be made.
</requirement>
</requirements>
