
	
<description>
The function `cmsCreateDeviceLinkFromCubeFile` creates a device link profile from a .cube file. It is a wrapper around `cmsCreateDeviceLinkFromCubeFileTHR`, which does the actual work. The function reads the .cube file, parses it to extract a color lookup table (CLUT) and an optional shaper table, and then creates an ICC profile with this information. The .cube file format is a text-based format that describes a 1D or 3D lookup table.
</description>
<requirements>
<requirement>
The input `cFileName` must be a non-NULL, null-terminated string. A NULL value will cause a crash due to an assertion failure in `cmsCreateDeviceLinkFromCubeFileTHR`.
</requirement>
<requirement>
The input `cFileName` must point to a readable file. The function uses `fopen` with the "rt" mode, so the file must exist and be accessible for reading.
</requirement>
<requirement>
The file content should conform to the Adobe Cube File Format. The parser expects specific keywords like 'TITLE', 'DOMAIN_MIN', 'DOMAIN_MAX', 'LUT_1D_SIZE', or 'LUT_3D_SIZE' followed by the appropriate data.
</requirement>
<requirement>
If `LUT_1D_INPUT_RANGE` or `LUT_3D_INPUT_RANGE` are present in the cube file, their values must be 0 and 1.0 respectively. The `ParseCube` function has a check for these values and will return an error if they are different.
</requirement>
<requirement>
The values for `DOMAIN_MAX` should be greater than the values for `DOMAIN_MIN`. The code computes divisors as `domain_max[i] - domain_min[i]`, so if `domain_max[i] <= domain_min[i]`, it can lead to a division-by-zero error.
</requirement>
<requirement>
The values for `LUT_1D_SIZE` and `LUT_3D_SIZE` in the cube file should be within a reasonable range. Very large values can lead to excessive memory allocation and potential denial of service.
</requirement>
</requirements>
