
	
<description>
The function `auth_zones_startprobesequence` starts a probe sequence for a given domain name. It finds the corresponding `auth_xfer` structure and initiates the process of sending probes. The function is called from `daemon/remote.c` to handle remote control commands.
</description>
<requirements>

<requirement>
The `az` argument, a pointer to a `struct auth_zones`, must be initialized. This is because the function accesses `az->lock` and `az->xtree`, so they must be valid.
</requirement>
<requirement>
The `auth_zones` struct should contain at least one `auth_xfer` entry. This is to ensure that `auth_xfer_find` can find and return a non-NULL value, allowing the function to proceed.
</requirement>
<requirement>
The `env` argument, a pointer to a `struct module_env`, must be properly initialized. This is because it is passed to `xfr_process_notify` and then to other functions which may use its members.
</requirement>
<requirement>
The `nm` argument must be a valid wire-format domain name, and `nmlen` must be its correct length. This is because `auth_xfer_find` uses these to find the transfer settings and `dname_count_labels` is called on `nm`.
</requirement>
<requirement>
The `dclass` argument should be a valid DNS class, such as `LDNS_RR_CLASS_IN`. This is used in `auth_xfer_find` to look up the authentication transfer information.
</requirement>

</requirements>
