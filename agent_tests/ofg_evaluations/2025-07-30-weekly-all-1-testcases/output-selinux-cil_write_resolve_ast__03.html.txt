
	
<description>
The `cil_write_resolve_ast` function is responsible for taking a CIL (Common Intermediate Language) database, which has been populated with data from a CIL policy file, and performing a series of transformations on it. It starts by building an Abstract Syntax Tree (AST) from the existing parse tree within the database. After the AST is successfully built, the original parse tree is destroyed to free up memory. Subsequently, the function resolves the symbols and relationships within the newly created AST, qualifies the names to ensure they are unique, and finally writes the resulting resolved AST to the provided output file stream. This function is one of several stages in the CIL policy compilation process, as seen in its caller `secil2tree`, which can write the AST at different phases (parse, build, resolve, post). The caller demonstrates that before calling any of the `cil_write_*_ast` functions, the CIL database must be initialized with `cil_db_init` and populated from one or more policy files using `cil_add_file`.
</description>

</requirement>
<requirement>
The `cil_add_file` function must be called to populate the database's parse tree (`db->parse`). This is because the first step within the target function, `cil_build_ast`, uses `db->parse->root` as its input to build the AST, and it will fail or crash if the parse tree is empty.
</requirement>
<requirement>
The `out` argument must be a valid file pointer opened for writing. This is because the function `cil_write_ast` will attempt to write the resolved AST to this file stream.
</requirement>
