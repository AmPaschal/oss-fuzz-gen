
	
<description>
The function `mutate_int` is a helper function used in the fuzzing harnesses of `libfido2`. It takes a pointer to an integer and uses `LLVMFuzzerMutate` to randomly change its value. This function is used to mutate different integer parameters within the fuzzing targets to explore different execution paths. In `fuzz_assert.c` and `fuzz_cred.c`, it is used to mutate an integer representing a bitmask of extensions (`ext`). In `fuzz_netlink.c`, it is used to mutate an integer representing a device handle (`dev`), which is unused in the dummy device implementation for fuzzing.
</description>

<requirement>
The integer pointer passed to `mutate_int` must be a valid, non-NULL pointer. This is because the function dereferences the pointer to determine the size of the memory to mutate and to pass the memory address to `LLVMFuzzerMutate`, and a NULL pointer would lead to a crash.
</requirement>
<requirement>
The integer pointed to by the argument to `mutate_int` should be a variable that affects the control flow of the program under fuzz. For example, in `fuzz_assert.c` and `fuzz_cred.c`, the mutated integer is a bitfield of extension flags that alters how `fido_assert_set_extensions` and `fido_cred_set_extensions` behave.
</requirement>
<requirement>
The integer passed to `mutate_int` represents different parameters depending on the fuzzing context. In `fuzz_assert.c` and `fuzz_cred.c`, it represents a bitmask of extensions (`FIDO_EXT_HMAC_SECRET`, `FIDO_EXT_CRED_BLOB`, `FIDO_EXT_LARGEBLOB_KEY`). In `fuzz_netlink.c`, it represents a device handle that is unused in the fuzzer's dummy implementation. The fuzzer should be aware of this context to interpret the results correctly.
</requirement>
