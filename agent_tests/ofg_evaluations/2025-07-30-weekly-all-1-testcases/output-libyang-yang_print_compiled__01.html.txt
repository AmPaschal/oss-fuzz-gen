
	
<description>
The function `yang_print_compiled` serializes a *compiled* YANG module (`lys_module`) into a specific output destination (`ly_out`). It's a low-level printer function for the "yang" format. It traverses the compiled schema tree (data nodes, RPCs, notifications, etc.) and prints their definitions. Its behavior is controlled by a set of `options` flags. It is not intended to be called directly, but rather through the `lys_print_module` API function when the output format is `LYS_OUT_YANG_COMPILED`.
</description>
<requirements>

<requirement>
The `out` parameter must be a valid pointer to a `struct ly_out` initialized by one of the `ly_out_new_*` functions, such as `ly_out_new_memory`. This is because the function writes its output to this struct and expects it to be in a valid state.
</requirement>
<requirement>
The `module` parameter must be a valid pointer to a `struct lys_module`, as the function dereferences this pointer to access module information.
</requirement>
<requirement>
The `module->compiled` field must not be NULL, as the function relies on the compiled representation of the module and will crash if it's missing. Use `lys_parse_mem` or `lys_parse_path` to load a module into a context, which will also compile it.
</requirement>
<requirement>
The `options` argument is a bitmask of flags that can be fuzzed to test different printing code paths. For example, the `LYS_PRINT_NO_SUBSTMT` flag will cause a large block of code that prints sub-statements to be skipped.
</requirement>

</requirements>
