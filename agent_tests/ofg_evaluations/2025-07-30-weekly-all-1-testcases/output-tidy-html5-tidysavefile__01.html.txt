
	
<description>
The `tidySaveFile` function saves the tidy document to the specified file. It is a wrapper around the `tidyDocSaveFile` function, which performs the actual saving. The `tidyDocSaveFile` function opens the specified file, saves the document stream to it, and then closes the file.
</description>
<requirements>

<requirement>
The first argument, `tdoc`, should be a valid `TidyDoc` object, created by calling `tidyCreate` and `tidyParseFile`, `tidyParseString`, or a similar parsing function. This is because the function expects a `TidyDoc` object that has been properly initialized and parsed.
</requirement>
<requirement>
The second argument, `filnam`, must be a valid, null-terminated string representing a writable file path. This is because the function passes this argument to `fopen` with the mode "wb", which will fail if the file path is invalid or not writable.
</requirement>
<requirement>
The `TidyForceOutput` option should be enabled in the `TidyDoc` configuration if you want to save the file even if there are errors. Otherwise, if there are errors and this option is disabled, the file will not be saved.
</requirement>

</requirements>

    // Parse the input to populate the TidyDoc. A document must be parsed

    tidyCleanAndRepair(tdoc);

    // is irrelevant as tidySaveFile will overwrite the file.

    if (!tmp_filename) {
        tidyRelease(tdoc);
        return 0;
    }

    // Call the function under test.
    tidySaveFile(tdoc, tmp_filename);

    // Clean up resources.
    fuzzer_release_tmpfile(tmp_filename);
    tidyRelease(tdoc);

    return 0;
}
