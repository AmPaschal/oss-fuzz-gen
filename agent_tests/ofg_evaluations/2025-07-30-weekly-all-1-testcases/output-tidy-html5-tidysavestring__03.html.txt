
	
<description>
The tidySaveString function saves a Tidy document to a user-provided string buffer. It is a wrapper for the tidyDocSaveString function, which performs the core logic of serializing the document into the buffer. The function takes a TidyDoc handle, a pointer to a character buffer, and a pointer to the buffer's length. It's designed to provide the cleaned and repaired HTML/XML content as a string. If the provided buffer is not large enough to hold the result, the function returns an error code and updates the length variable to indicate the required buffer size.
</description>
<requirements>
<requirement>
The first argument, tdoc, must be a valid TidyDoc object. This is because the function internally converts it to a TidyDocImpl object to access document-specific information like configuration and the document tree.
</requirement>
<requirement>
The tdoc object must be initialized by calling tidyCreate() and then populated with data using a parsing function like tidyParseString(). This ensures there is content to be saved to the string buffer.
</requirement>
<requirement>
The second argument, buffer, must be a non-NULL pointer to a valid memory buffer. This buffer is where the saved document will be stored.
</requirement>
<requirement>
The third argument, buflen, must be a non-NULL pointer to an unsigned integer. This integer represents the size of the provided buffer.
</requirement>
<requirement>
The value pointed to by buflen must be greater than or equal to the size of the serialized document. This is to prevent a buffer overflow, as the function copies the saved data into the user-provided buffer.
</requirement>
</requirements>
