
	
<description>
The `nxt_process_init_start` function initializes and starts a new process. It allocates a new process structure, sets its parent port, name, and user credentials from the runtime environment and the provided `init` structure. The function then copies the `init` structure to the newly allocated process's initialization data and calls `nxt_process_start` to begin the process execution. Callers of this function are part of the main process startup and signal handling logic, which indicates that this function is central to process management in the application. The `init` parameter is consistently one of a set of globally defined `nxt_process_init_t` structs, which suggests these are the only valid configurations for new processes.
</description>
<requirements>
<requirement>
The `task` argument must be a valid pointer to a `nxt_task_t` struct, with `task->thread` and `task->thread->runtime` also being valid pointers. This is to prevent null pointer dereferences when accessing runtime state.
</requirement>
<requirement>
The `init` argument should be initialized from one of the global variables: `nxt_controller_process`, `nxt_router_process`, or `nxt_discovery_process`. These globals contain the correct and safe configurations for starting a new process.
</requirement>
<requirement>
The `name` field of the `init` structure must be a null-terminated string. This prevents potential buffer overflows or memory access violations.
</requirement>
<requirement>
The function pointers `prefork`, `setup`, and `start` within the `init` struct must either be NULL or point to valid functions. Using one of the global initializer objects for `init` will satisfy this requirement.
</requirement>
<requirement>
The `task->thread->runtime->port_by_type` array must be initialized before calling this function. This is because it is accessed to set the `parent_port` of the new process.
</requirement>
</requirements>
