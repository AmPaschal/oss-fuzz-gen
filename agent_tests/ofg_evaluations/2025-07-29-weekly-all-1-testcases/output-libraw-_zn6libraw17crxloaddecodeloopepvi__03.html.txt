
	
<description>
The `LibRaw::crxLoadDecodeLoop` function is responsible for decoding the image data of a CRX file, plane by plane. It iterates through the number of planes specified by the `nPlanes` argument, and for each plane, it calls the `crxDecodePlane` function. The `crxDecodePlane` function handles the actual decoding process for a single plane, which includes setting up subband data, performing inverse wavelet transforms, and dequantization. The first argument, `img`, is a pointer to a `CrxImage` struct that holds all the necessary data and buffers for the decoding process. This function can be compiled with OpenMP support to decode multiple planes in parallel.
</description>
<requirements>
<requirement>
The first argument `img` must be a pointer to a `CrxImage` struct that has been initialized by the `crxSetupImageData` function. This is because `crxLoadDecodeLoop` and its callees rely on the data structures and buffers within the `CrxImage` struct to be properly set up for decoding.
</requirement>
<requirement>
The `input` field of the `CrxImage` struct must point to a valid `LibRaw_abstract_datastream` object. The decoding functions use this stream to read the raw image data, and a null or invalid pointer will cause a crash.
</requirement>
<requirement>
The `nPlanes` argument must be either 1 or 4. This is enforced by the file format parsing logic, and using other values can lead to out-of-bounds memory access or other undefined behavior.
</requirement>
<requirement>
A sufficiently large buffer must be allocated for the `outBuf` argument of the `crxSetupImageData` function, which is used to initialize the `img` struct. The decoded image data is written into this buffer, and an insufficient size will result in a buffer overflow.
</requirement>
<requirement>
The `crxFreeImageData` function must be called on the `CrxImage` struct after `crxLoadDecodeLoop` returns. This is necessary to release the memory that was allocated during the decoding process and prevent memory leaks.
</requirement>
</requirements>

#include <cstddef>
#include <cstdint>

#include "libraw.h"

// It is not possible to directly call LibRaw::crxLoadDecodeLoop from a fuzzer.
// The function requires a `void *` that points to a `CrxImage` struct.
// This struct is defined internally within a .cpp file (`src/decoders/crx.cpp`)
// and is not exposed through any public header. The function that initializes
// this struct, `crxSetupImageData`, is also static to that .cpp file.
//
// The correct way to fuzz this function is to call the public API that uses it.
// `LibRaw::unpack()` will, for CRX/CR3 files, internally set up the
// necessary data structures and call `crxLoadDecodeLoop`. This fuzzer
// therefore calls `open_buffer` followed by `unpack` to trigger the target
// function.

extern "C" int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
  LibRaw image_processor;

  // open_buffer will parse the provided data. If it's a CRX/CR3 file,
  // it will prepare the internal structures needed for decoding.
  if (image_processor.open_buffer(data, size) != LIBRAW_SUCCESS) {
    return 0;
  }

  // unpack() will start the decoding process. For a CRX/CR3 file, this
  // will lead to an internal call to crxLoadDecodeLoop with a properly
  // initialized CrxImage struct.
  image_processor.unpack();

  // The LibRaw destructor will handle freeing all allocated resources.
  return 0;
}
