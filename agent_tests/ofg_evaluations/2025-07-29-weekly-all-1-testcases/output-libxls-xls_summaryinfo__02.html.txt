
	
<description>
The `xls_summaryInfo` function extracts summary information from an Excel workbook. It takes a pointer to an `xlsWorkBook` structure, which represents a loaded Excel file. Inside the function, it allocates a new `xlsSummaryInfo` structure. It then calls the `xls_dumpSummary` function twice: once for the main summary information (`pWB->summary`) and once for the document summary information (`pWB->docSummary`). These `summary` and `docSummary` fields are expected to be pointers to character buffers containing OLE property sets. The `xls_dumpSummary` function parses these buffers to populate the fields of the allocated `xlsSummaryInfo` structure (like title, author, subject, etc.). Finally, the function returns the populated `xlsSummaryInfo` pointer. To use this function correctly, one must first open an XLS file (e.g., from a buffer using `xls_open_buffer`) to obtain a valid `xlsWorkBook` pointer.
</description>
<requirements>
<requirement>
The `xlsWorkBook` pointer argument `pWB` must be initialized by calling `xls_open_buffer`. This is because `xls_open_buffer` is responsible for parsing the input file and setting up the internal structures, including the `summary` and `docSummary` streams that `xls_summaryInfo` relies on.
</requirement>
<requirement>
The `pWB->summary` and `pWB->docSummary` members must either be NULL or point to valid OLE summary information streams. The `xls_dumpSummary` function, called by `xls_summaryInfo`, will crash if it attempts to parse invalid, non-NULL data.
</requirement>
<requirement>
After the `xlsWorkBook` is no longer needed, `xls_close_WB` should be called to release its resources. This prevents memory leaks, as `xls_open_buffer` allocates memory for the workbook structure and its contents.
</requirement>
<requirement>
The returned `xlsSummaryInfo` pointer should be passed to `xls_close_summaryInfo` when it is no longer needed. This is to free the memory allocated for the summary information structure and its string fields by `xls_summaryInfo` and `xls_dumpSummary`.
</requirement>
</requirements>
