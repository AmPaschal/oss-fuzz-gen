
	
<description>
The function `cmsCreateDeviceLinkFromCubeFile` creates a device link profile from a CUBE file. It acts as a wrapper for `cmsCreateDeviceLinkFromCubeFileTHR`, passing a NULL context ID. The core logic within `cmsCreateDeviceLinkFromCubeFileTHR` opens and reads the CUBE file specified by `cFileName`, which is then parsed by the `ParseCube` function to extract the shaper and CLUT (Color Look-Up Table) data. This information is subsequently used to create an ICC device link profile. The function manages the allocation and deallocation of memory for all internal structures it utilizes.
</description>
<requirements>
<requirement>
The `cFileName` argument must be a non-NULL, null-terminated string that represents a valid and readable file path. This is because the function directly passes this argument to `fopen` to open the file for reading, and a NULL value will trigger an assertion failure.
</requirement>
<requirement>
The file specified by `cFileName` must adhere to the Adobe Cube file format. The `ParseCube` function is responsible for parsing this file, and any deviation from the expected format will cause parsing to fail, resulting in a NULL return value.
</requirement>
<requirement>
The CUBE file must contain either the `LUT_1D_SIZE` or `LUT_3D_SIZE` keyword. These keywords are essential for the `ParseCube` function to determine the size of the shaper and CLUT, respectively; without them, the resulting profile will lack the necessary color transformation data.
</requirement>
<requirement>
If the CUBE file includes the `LUT_1D_INPUT_RANGE` or `LUT_3D_INPUT_RANGE` keywords, their values must be 0.0 and 1.0. The `ParseCube` function enforces this requirement, and any other range will lead to a parsing error.
</requirement>
<requirement>
The number of data points in the CUBE file must correspond to the dimensions specified by the `LUT_1D_SIZE` and `LUT_3D_SIZE` keywords. A mismatch between the declared sizes and the actual number of data points will cause `ParseCube` to either fail or parse the data incorrectly.
</requirement>
</requirements>
