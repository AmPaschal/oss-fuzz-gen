
	
<description>
The `mutt_get_postponed` function retrieves a postponed message from a designated "postponed" mailbox. It takes the current mailbox `m_cur`, a header struct `hdr` for the new message, a pointer `cur` to store a related email, and a buffer `fcc` to store the Fcc path.

The function first locates the postponed mailbox. If this mailbox is different from the current mailbox, it opens it. It checks if there are any messages in the postponed mailbox; if not, it returns an error. If there is more than one message, it prompts the user to select one.

Once a postponed message is selected, the function prepares it as a template for the new message. It then processes the headers of the new message (`hdr`), looking for special headers like `Mutt-References`, `Mutt-Fcc`, and crypto-related headers. It extracts information from these headers, such as the reference to the original message (updating `*cur`) and the Fcc path (updating `fcc`). These special headers are then removed from the new message. Finally, the function marks the retrieved postponed message for deletion and returns a status code indicating the actions taken.
</description>
<requirements>
<requirement>
The global variable `NeoMutt` must be initialized before calling the function. The function depends on configuration settings stored in `NeoMutt->sub` to find the postponed mailbox and get other settings.
</requirement>
<requirement>
The second argument, `hdr`, must be a valid pointer to an `Email` struct, allocated by `email_new()`. This is because the function accesses and modifies members of this struct, including `hdr->env->userhdrs` and `hdr->security`.
</requirement>
<requirement>
The `env` member of the `hdr` argument must be initialized, for example, by `mutt_env_new()`. The function iterates over the `userhdrs` list within the `env` struct.
</requirement>
<requirement>
The fourth argument, `fcc`, must be a valid pointer to a `Buffer` struct, allocated by `buf_pool_get()`. The function may write to this buffer using `buf_strcpy`.
</requirement>
<requirement>
A mailbox designated as "postponed" in the configuration must exist and contain at least one email. The function will fail if it cannot open this mailbox or if the mailbox is empty.
</requirement>
<requirement>
The third argument, `cur`, must be a valid pointer to an `Email` pointer. It is used as an output parameter to store a pointer to an email found in the current mailbox.
</requirement>
</requirements>
