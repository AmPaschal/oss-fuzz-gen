
	
<description>
The `mbedtls_ssl_write_early_data` function is used by a TLS 1.3 client to send data to the server before the handshake is fully complete. This is only possible if the client is resuming a session and the server has indicated that it will accept early data. The function will attempt to send the provided data, but may not be able to if the server rejects early data, the maximum amount of early data has been sent, or the handshake has progressed past the point where early data is allowed. The caller must be prepared to handle the `MBEDTLS_ERR_SSL_CANNOT_WRITE_EARLY_DATA` error and fall back to a normal handshake.
</description>
<requirements>

<requirement>
The `mbedtls_ssl_context` must be configured as a client with TLS 1.3 and early data enabled. This is done by calling `mbedtls_ssl_config_defaults`, `mbedtls_ssl_conf_min_tls_version`, `mbedtls_ssl_conf_max_tls_version`, and `mbedtls_ssl_conf_early_data` on the associated `mbedtls_ssl_config` structure.
</requirement>
<requirement>
A valid session with a PSK and an indication that the server accepts early data must be loaded into the context using `mbedtls_ssl_set_session`. This session is obtained from a previous successful TLS 1.3 handshake.
</requirement>
<requirement>
The transport type must be stream-based (MBEDTLS_SSL_TRANSPORT_STREAM). The function will return an error if the transport type is datagram-based.
</requirement>
<requirement>
The `buf` parameter should be a valid pointer to a buffer of at least `len` bytes, or NULL if `len` is 0. This buffer contains the application data to be sent and can be fuzzed.
</requirement>
<requirement>
The `len` parameter specifies the number of bytes to send from `buf`. This value can be 0. The actual number of bytes sent may be less than `len` if the maximum early data size for the session is exceeded.
</requirement>
<requirement>
The caller must be prepared to handle the `MBEDTLS_ERR_SSL_CANNOT_WRITE_EARLY_DATA` return code. This indicates that early data cannot be sent at the current time, and the application should proceed with a regular handshake using `mbedtls_ssl_handshake`.
</requirement>

</requirements>

int fuzz_recv(void *ctx, unsigned char *buf, size_t len) {
  fuzzBufferOffset_t *biomem = (fuzzBufferOffset_t *)ctx;
  if (biomem->Size == 0) {
    return MBEDTLS_ERR_SSL_WANT_READ;
  }
  if (len > biomem->Size - biomem->Offset) {
    len = biomem->Size - biomem->Offset;
  }
  if (len > 0) {
    memcpy(buf, biomem->Data + biomem->Offset, len);
    biomem->Offset += len;
  }
  return len;
}
