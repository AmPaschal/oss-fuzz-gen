
	
<description>
The `kexgex_server` function is a server-side function that initiates the Diffie-Hellman Group Exchange (DH-GEX) key exchange process. It does this by registering the `input_kex_dh_gex_request` function as the handler for the `SSH2_MSG_KEX_DH_GEX_REQUEST` message. The actual logic for handling the key exchange is contained within `input_kex_dh_gex_request` and subsequent functions in the chain. The `kexgex_server` function itself is not called directly but is assigned as a function pointer within the `kex` structure of an `ssh` session object.
</description>
<requirements>
<requirement>
The `ssh` argument must be a valid pointer to a `struct ssh` initialized by `ssh_alloc_session_state`. This is to ensure that the `ssh` object and its substructures, such as `ssh->kex`, are properly allocated and initialized, preventing null pointer dereferences.
</requirement>
<requirement>
The `ssh->kex->dh` field must be initialized to a valid `DH` object. This is because the callback registered by `kexgex_server`, `input_kex_dh_gex_request`, will use this `DH` object to perform key generation.
</requirement>
<requirement>
The `ssh` object must have its input buffers populated with a `SSH2_MSG_KEX_DH_GEX_REQUEST` message. The `input_kex_dh_gex_request` callback reads the client's parameters from the network buffer, and these parameters must be present for the function to execute correctly.
</requirement>
</requirements>

#include "/src/hpn-ssh/kexgexs.c"

// Main fuzzing entry point
extern "C" int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    static bool initialized = false;
    if (!initialized) {
        // Initialize logging to avoid crashes in logging functions.
        log_init("kexgex_server_fuzz", SYSLOG_LEVEL_ERROR, SYSLOG_FACILITY_USER, 1);
        initialized = true;
    }

    FuzzedDataProvider provider(data, size);

    // ssh_alloc_session_state also allocates the kex struct.
    struct ssh *ssh = ssh_alloc_session_state();
    if (ssh == NULL) {
        return 0;
    }

    // kexgex_server is a server-side function.
    ssh_packet_set_server(ssh);

    // The handler input_kex_dh_gex_request reads three u32 values (min, nbits, max)
    // from the incoming packet buffer. We populate this buffer with fuzzed data.
    struct sshbuf *incoming_packet = (struct sshbuf *)ssh_packet_get_input(ssh);
    sshbuf_reset(incoming_packet);
    if (sshbuf_put_u32(incoming_packet, provider.ConsumeIntegral<uint32_t>()) != 0 ||
        sshbuf_put_u32(incoming_packet, provider.ConsumeIntegral<uint32_t>()) != 0 ||
        sshbuf_put_u32(incoming_packet, provider.ConsumeIntegral<uint32_t>()) != 0) {
        ssh_free(ssh);
        return 0;
    }

    // Call the function-under-test as required by the prompt.
    // This sets up the dispatch handler for SSH2_MSG_KEX_DH_GEX_REQUEST.
    kexgex_server(ssh);

    // To effectively fuzz the logic, we directly call the static handler that
    // was just registered. This bypasses the complex packet dispatching
    // mechanism and focuses the fuzzing effort on the GEX request logic.
    // We ignore the return value as the function may fail due to invalid fuzzed
    // inputs, which is the intended behavior.
    input_kex_dh_gex_request(SSH2_MSG_KEX_DH_GEX_REQUEST, 0, ssh);

    // ssh_free will also free the kex struct and its members, including kex->dh.
    ssh_free(ssh);

    return 0;
}
