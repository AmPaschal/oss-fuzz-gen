
	
<description>
The `mbedtls_ssl_write` function is used to write application data to an established SSL/TLS connection. It takes an SSL context, a buffer containing the data, and the length of the data as input. Before this function can be called, a complete SSL/TLS handshake must have been performed to bring the connection state to `MBEDTLS_SSL_HANDSHAKE_OVER`. The function handles the process of encrypting the data and sending it over the underlying transport. For TLS, it can fragment large buffers into multiple records. For DTLS, it expects the buffer size to be within the negotiated maximum fragment length.
</description>
<requirements>
<requirement>
The `mbedtls_ssl_context` object must be initialized by calling `mbedtls_ssl_init()` and `mbedtls_ssl_setup()`. This is because the `mbedtls_ssl_context` is a complex structure with many internal fields that must be set to a consistent state, which is handled by these initialization functions.
</requirement>
<requirement>
The `mbedtls_ssl_config` object, passed to `mbedtls_ssl_setup`, must be initialized, for example using `mbedtls_ssl_config_init` and `mbedtls_ssl_config_defaults`. This is because the SSL context relies on a valid configuration to be set up correctly, including endpoint role (client/server), ciphersuites, and other security parameters.
</requirement>
<requirement>
The I/O callbacks must be set for the SSL context using `mbedtls_ssl_set_bio()`. The `mbedtls_ssl_write` function uses these callbacks to send the encrypted data over the network and will fail without them.
</requirement>
<requirement>
A successful SSL/TLS handshake must be completed by calling `mbedtls_ssl_handshake()` before calling `mbedtls_ssl_write()`. This is because `mbedtls_ssl_write` checks if the SSL state is `MBEDTLS_SSL_HANDSHAKE_OVER` and requires the handshake to be established for writing application data.
</requirement>
<requirement>
The second argument, `buf`, should be a valid pointer to a buffer of at least `len` bytes. The function reads `len` bytes from this buffer to send as application data, and an invalid pointer or insufficient buffer size will lead to a crash.
</requirement>
<requirement>
The third argument, `len`, should be fuzzed to test the handling of different data lengths. This is to ensure the function's ability to handle fragmentation in TLS and size limits in DTLS is robust against various input sizes.
</requirement>
</requirements>
