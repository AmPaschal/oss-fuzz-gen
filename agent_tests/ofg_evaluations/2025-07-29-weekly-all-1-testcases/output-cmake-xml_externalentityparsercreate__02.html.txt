
	
<description>
The `XML_ExternalEntityParserCreate` function is used to create a new XML parser for handling external entities. It's a specialized parser that inherits much of its configuration, including handlers and the Document Type Definition (DTD), from an existing parent parser, `oldParser`. The new parser's behavior is tailored based on the `context` string, which initializes the entity and namespace environment. The `encodingName` parameter dictates the character encoding for the external entity's data. This function is essential for modularly parsing external DTDs or entity references encountered during the parsing of a primary XML document. The newly created parser maintains a link to its parent, forming a hierarchical parsing structure.
</description>
<requirements>
<requirement>
The first argument, oldParser, must be a valid, non-NULL pointer to an XML_Parser struct. The function's first action is to check for NULL and it subsequently accesses multiple members of this struct to configure the new parser.
</requirement>
<requirement>
The oldParser argument should be created by a call to XML_ParserCreate or XML_ParserCreate_MM. This ensures that the parser's internal state, particularly its memory management and DTD structures, are properly initialized before being inherited.
</requirement>
<requirement>
The context argument must be a null-terminated string, but a NULL pointer is also acceptable. If non-NULL, it needs to be a space-separated list of entity names or namespace definitions (prefix=URI), as it is processed by the setContext function to correctly initialize the parsing environment.
</requirement>
<requirement>
The encodingName argument should be a null-terminated string representing a supported character encoding (like 'UTF-8') or be NULL. An invalid encoding name will cause the underlying parserCreate function to fail, leading to a NULL return from this function.
</requirement>
</requirements>
