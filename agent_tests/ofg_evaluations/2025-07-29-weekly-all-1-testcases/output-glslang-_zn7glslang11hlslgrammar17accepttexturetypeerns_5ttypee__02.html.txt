The function `HlslGrammar::acceptTextureType` is responsible for parsing a texture type declaration in HLSL. It consumes tokens from a token stream and populates a `TType` object with the parsed information. The function expects the current token in the stream to be a texture type keyword. It then proceeds to parse optional template arguments (like the texture's data type and multisample count) and other attributes. The function relies on the `HlslParseContext` to validate and store the parsed texture information.
</description>

</requirement>
<requirement>

</requirement>
<requirement>
If the texture type is a multisampled texture (`EHTokTexture2DMS` or `EHTokTexture2DMSarray`), the token stream should contain a subsequent integer literal for the sample count. The function expects to parse an integer literal for the sample count for multisampled textures if it is provided inside angle brackets, and failure to provide this will result in a parsing error.
</requirement>
<requirement>
If the texture type is a `RWTexture` or `RWBuffer`, the token stream must contain a type parameter within angle brackets. The code explicitly checks for this and will raise a 'type for RWTexture/RWBuffer' error if the type parameter is missing.
</requirement>
<requirement>
The `TType` object passed as an argument will be completely overwritten. The function calls `type.shallowCopy(...)` at the end, which replaces the content of the `type` object, so its initial state does not matter.
</requirement>
