
	
<description>
The `tidySaveStdout` function saves the contents of a `TidyDoc` object to the standard output. It is a wrapper around the internal `tidyDocSaveStdout` function, which in turn uses a `TidyOutputSink` to direct the output. For the function to work correctly, the `TidyDoc` object must be created and populated with a parsed document, which is then cleaned and diagnosed before being saved.
</description>
<requirements>

<requirement>
The `tdoc` argument must be a valid `TidyDoc` object created by `tidyCreate()`. This is because the function expects a valid, initialized `TidyDocImpl` structure, and passing an invalid or NULL pointer will lead to a crash.
</requirement>
<requirement>
A document must be parsed into the `TidyDoc` object using a function like `tidyParseString()`, `tidyParseFile()`, or `tidyParseStdin()`. This is because `tidySaveStdout` is designed to save a parsed document, and there will be no content to save otherwise.
</requirement>
<requirement>
The `tidyCleanAndRepair()` function should be called after parsing the document and before calling `tidySaveStdout()`. This function performs essential cleanup and repair operations on the parsed document tree, preparing it for output.
</requirement>
<requirement>
The `tidyRunDiagnostics()` function must be called before `tidySaveStdout()`. This function generates diagnostic information about the document, which is a key part of the output process.
</requirement>

</requirements>
