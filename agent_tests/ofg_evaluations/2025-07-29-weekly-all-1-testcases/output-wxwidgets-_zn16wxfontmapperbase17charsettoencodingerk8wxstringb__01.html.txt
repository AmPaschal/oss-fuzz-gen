The function `wxFontMapperBase::CharsetToEncoding` is responsible for converting a character set name, provided as a string, into a corresponding `wxFontEncoding` enumeration value. It is a central piece of functionality in wxWidgets for handling font encodings across different platforms and configurations.

The function's core logic, primarily located in the helper function `NonInteractiveCharsetToEncoding`, follows a specific order of operations to resolve the character set name:
1.  **Configuration Lookup:** It first attempts to find a user-defined mapping or alias for the input `charset` string within a `wxConfig` object. This allows for customization and overriding the default behavior.
2.  **Static Table Search:** If no configuration is found, it cleans up the input string by trimming whitespace and removing quotes. It then performs a case-insensitive search through a large, pre-defined table (`gs_encodingNames`) containing a comprehensive list of standard and non-standard charset names and their aliases.
3.  **Pattern Matching:** If the charset name is not in the static table, the function tries to parse it based on common patterns. It specifically looks for strings starting with "ISO", "CP", or "WINDOWS" (e.g., "iso-8859-1", "cp1252") and extracts the numeric part to identify the encoding.
4.  **Default Fallback:** If all previous steps fail to identify a valid encoding, the function returns `wxFONTENCODING_SYSTEM`, ensuring a safe fallback.

The callers of this function are diverse, ranging from internal string conversion and font handling logic to user-facing components that load resources from files (like XML). This indicates that the `charset` input can come from a wide variety of sources, including potentially untrusted user data, making robust handling of this input critical. The second boolean parameter, `interactive`, is consistently unused in the codebase.
