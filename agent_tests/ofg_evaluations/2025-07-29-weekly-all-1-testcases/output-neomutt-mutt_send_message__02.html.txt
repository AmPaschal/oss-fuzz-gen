
	
<description>
This function, `mutt_send_message`, is the central function for sending email messages in NeoMutt. It's a complex function that handles various scenarios, including composing new emails, replying, forwarding, resending, and handling postponed messages. Its behavior is highly configurable and determined by the `SendFlags` argument and the `ConfigSubset` which provides access to numerous configuration options.

The function orchestrates the entire process of sending a message:
1.  **Initialization**: It sets up the email structure (`struct Email`), either by creating a new one or by using the provided template (`e_templ`). It also handles recalling postponed messages.
2.  **Envelope Editing**: It allows for editing the email envelope (To, From, Cc, Bcc, Subject, etc.), processing user-defined headers, and expanding aliases.
3.  **Body Generation**: It prepares the message body, which can involve including quoted text from a replied-to message, attaching files, and adding signatures.
4.  **Crypto Operations**: It handles message signing and encryption (PGP and S/MIME) based on user configuration and the context of the message.
5.  **User Interaction**: It interacts with the user through dialogs to confirm actions, edit the message, and handle errors.
6.  **Sending**: Finally, it invokes the Mail Transfer Agent (MTA) to actually send the email and saves a copy to an FCC (Folder Carbon Copy) mailbox if configured.

The callers of this function are diverse, reflecting the many ways a message can be sent from within NeoMutt, such as from the index, the attachment screen, or via alias expansion. Each caller sets the `flags` and provides the necessary context (like the original message being replied to) to guide the function's behavior. Because it touches many parts of the system (configuration, crypto, file I/O, user interface), its correct execution depends on a properly initialized program state.
</description>

</requirement>
<requirement>
The `e_templ` argument can be NULL, in which case a new email is created. If it is not NULL, it must point to a valid `struct Email` object, typically initialized with `email_new()` and `mutt_env_new()`.
</requirement>
<requirement>
If the `flags` argument includes `SEND_DRAFT_FILE`, the `e_templ->body->filename` field must be set to a valid file path. The function attempts to open this file for appending, and a NULL or invalid path will cause an error.
</requirement>
<requirement>
The `tempfile` argument can be NULL. If it is not NULL, it must be a path to a file that can be opened for writing. The function will attempt to open it with "a+" mode.
</requirement>
<requirement>
The `ea` argument can be NULL. If it's not NULL, it must point to a valid, initialized `EmailArray` struct. The function accesses elements of this array, so an uninitialized pointer would cause a crash.
</requirement>
<requirement>
The `m` argument can be NULL. If it is not NULL, it must point to a valid `struct Mailbox`. The function accesses members of `m` (e.g., `m->type`, `m->mdata`) under certain conditions determined by the `flags` argument.
</requirement>
<requirement>
The `flags` argument controls the overall behavior of the function. It should be set to one or a combination of the `SendFlags` enum values, based on the intended operation (e.g., `SEND_REPLY`, `SEND_POSTPONED`, `SEND_NEWS`).
</requirement>
</requirements>
