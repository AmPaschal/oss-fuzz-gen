
	
<description>
The function `is_legal_2d_block_size` checks if a given 2D block dimension (`xdim`, `ydim`) is one of the 14 legal block sizes supported by the ASTC standard. It does this by combining `xdim` and `ydim` into a single `unsigned int` and using a `switch` statement to check against the valid hexadecimal representations of these pairs. The function is called by `validate_block_size` as part of the configuration validation process in `astcenc_config_init`. For the compression or decompression to proceed, this function must return `true`.
</description>
<requirements>
<requirement>
The input parameters `xdim` and `ydim` must be one of the following 14 pairs: (4,4), (5,4), (5,5), (6,5), (6,6), (8,5), (8,6), (8,8), (10,5), (10,6), (10,8), (10,10), (12,10), (12,12). This is because any other combination of `xdim` and `ydim` will cause the function to return `false`, leading to a `ASTCENC_ERR_BAD_BLOCK_SIZE` error, which will prevent further execution.
</requirement>
<requirement>
The input parameters `xdim` and `ydim` should be fuzzed, but guided to select from the legal pairs. This is because the values originate from the public API function `astcenc_config_init`, making them user-controlled, and providing valid pairs allows the fuzzer to explore paths beyond the initial block size validation.
</requirement>
</requirements>
