
	
<description>
The function `Eval` evaluates a mathematical expression in bulk. It takes an array `results` and its size `nBulkSize` as input. For each `i` from 0 to `nBulkSize-1`, it evaluates the expression and stores the result in `results[i]`. Before the evaluation, it calls `CreateRPN()` to convert the expression from infix notation to Reverse Polish Notation (RPN). The actual calculation is performed by the `ParseCmdCodeBulk` function.
</description>
<requirements>

<requirement>
The `SetExpr` method must be called before calling `Eval`. This is because `Eval` internally calls `CreateRPN`, which requires an expression to be set in the `ParserBase` object.
</requirement>
<requirement>
The `results` pointer must not be NULL. It must point to a valid memory block of at least `nBulkSize * sizeof(value_type)` bytes, as the function will write the evaluation results into this buffer.
</requirement>
<requirement>
The `nBulkSize` argument should be a non-negative integer. This is because it is used as the upper bound in a for loop, and a negative value would cause the loop to not execute, while a very large value could lead to excessive memory allocation and long execution times.
</requirement>

</requirements>

#include <fuzzer/FuzzedDataProvider.h>
#include <string>
#include <vector>

#include "muParser.h"

extern "C" int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
  FuzzedDataProvider provider(data, size);

  std::string expr = provider.ConsumeRandomLengthString();
  const int nBulkSize = provider.ConsumeIntegralInRange<int>(0, 1024);

  try {
    mu::Parser parser;
    parser.SetExpr(expr);

    // Use `double` directly as the underlying type for `value_type`
    // to resolve the compilation error.
    std::vector<double> results(nBulkSize);

    if (nBulkSize > 0) {
      parser.Eval(results.data(), nBulkSize);
    } else {
      parser.Eval(nullptr, 0);
    }

  } catch (mu::Parser::exception_type &e) {
    // Catch parser exceptions.
  } catch (mu::ParserError &e) {
    // Catching this as well, just in case exception_type is not a typedef for it.
  }

  return 0;
}
