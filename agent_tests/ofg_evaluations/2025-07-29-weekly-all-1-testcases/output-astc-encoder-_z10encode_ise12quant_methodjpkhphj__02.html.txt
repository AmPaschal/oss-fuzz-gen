
	
<description>
The `encode_ise` function encodes a sequence of characters using the Integer Sequence Encoding (ISE) method. The encoding is determined by the `quant_level`, which specifies the number of bits, trits, and quints to use. The function reads from an input buffer, encodes the data, and writes the resulting bitstream to an output buffer, starting at a given bit offset.
</description>
<requirements>
<requirement>
The `quant_level` parameter must be an integer between 2 and 12, inclusive. This is because `quant_level` is used to index the `btq_counts` array, which has a size of 13 and valid indices from 0 to 12. Since the enum `quant_method` starts from 0, the valid range for `quant_level` as an integer is 0-12, but the code seems to use values from 2 to 12.
</requirement>
<requirement>
The `character_count` parameter must be greater than 0. The function includes a `promise(character_count > 0)` which will cause a crash if this condition is not met.
</requirement>
<requirement>
The `input_data` pointer must not be null and should point to a buffer of at least `character_count` bytes. A null pointer would cause a crash when the function tries to read from this buffer.
</requirement>
<requirement>
The `output_data` pointer must not be null and should point to a buffer large enough to hold the encoded data. A null pointer or an insufficiently sized buffer would lead to a crash or memory corruption when the function writes the encoded data.
</requirement>
<requirement>
The values in the `input_data` buffer should be less than `(1 << btq_counts[quant_level].bits)`. This is because the function uses a mask of `(1 << bits) - 1` to extract the lower bits of the input data, and shifting by `bits` to get the higher bits for indexing into the `integer_of_trits` and `integer_of_quints` tables.
</requirement>
