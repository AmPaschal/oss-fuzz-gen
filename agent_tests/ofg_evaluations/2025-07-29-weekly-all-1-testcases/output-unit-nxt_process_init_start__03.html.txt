
	
<description>
The `nxt_process_init_start` function initializes and starts a new process. It allocates a new process structure, copies the initialization parameters from the `init` argument, and then calls `nxt_process_start` to actually start the process. The callers typically pass one of the global `nxt_process_init_t` structures like `nxt_controller_process`, `nxt_router_process`, or `nxt_discovery_process` as the `init` argument.
</description>
<requirements>
<requirement>
The `task` argument must be a valid pointer to an initialized `nxt_task_t` structure. The function accesses `task->thread->runtime` so this must not be NULL.
</requirement>
<requirement>
The `init` argument should be initialized with the values from one of the global variables: `nxt_controller_process`, `nxt_router_process`, or `nxt_discovery_process`. This ensures that all the function pointers and other fields in the struct are valid.
</requirement>
<requirement>
The `init.name` field of the `init` argument must be a null-terminated string. This is because it is assigned to the `name` field of the new process structure and used for identification.
</requirement>
<requirement>
The `task->thread->runtime->port_by_type` array must be initialized. The function uses the `type` field from the `init` argument to index into this array, so it must be large enough and contain valid port information.
</requirement>
</requirements>

int
LLVMFuzzerTestOneInput(const uint8_t *data, size_t size)
{
    nxt_task_t    *task;
    nxt_thread_t  *thr;

    thr = nxt_thread();
    if (thr == NULL) {
        return 0;
    }

    task = thr->task;

    /*
     * The fuzzer input is ignored because the parameters to the target
     * function are complex stateful structures that cannot be generated
     * from raw bytes. Instead, we call the function with valid,
     * pre-initialized global configurations.
     */

    nxt_process_init_start(task, nxt_controller_process);
    nxt_process_init_start(task, nxt_router_process);
    nxt_process_init_start(task, nxt_discovery_process);

    /*
     * No specific cleanup is performed. The fuzzer relies on the
     * process-per-input model to release resources, as process lifecycle
     * management in Unit is complex and handled by signal handlers.
     */

    return 0;
}
